# Contributing

Contributions of all kinds are welcome! Ask a question, share an example, or point out where the docs could be clearer.
Teaching, mentoring, scientific review, code, and tests help too.
You’re welcome to join in whenever you have time, at any experience level.

## Making a change

The package’s contributor guide is a good place to start. Here’s how we usually work together.

- Spot a typo or a broken example? Feel free to open a pull request.
- Talk with the maintainers early if you’re planning a bigger change. This includes new features and changes to dependencies, APIs, or statistical methods.
- Keep each pull request focused. A quick note on the tests you ran or the examples you tried helps reviewers understand what you checked.

Feel free to share an early draft or ask a maintainer for help with tests or docs.
When we review your work, we’ll explain which changes we need and which are suggestions.

We aim to follow [ColPrac](https://github.com/SciML/ColPrac), with room for package teams to adapt it, including solo maintainers.

## Licensing and credit

When you contribute, you make your changes available under the license for that part of the repository.
Some repositories use different licenses for code and documentation, so check which one applies before opening a pull request.

Give people credit for their work, whether they wrote code, improved the docs, or mentored someone.
Ask how they’d like to be credited. Some people prefer a handle or a private thank-you.

## Finding help

Got a question about a package? Its GitHub issues or Discussions are a good place to ask.
If something goes wrong, tell us what you expected, what happened, and which Julia and package versions you used.
Share a small example with made-up data if your data is private.

Looking for a place to start? Open a [welcome issue](https://github.com/JuliaBayes/.github/issues/new?template=welcome.md).
Come say hello in `#bayes` on [Julia Slack](https://julialang.org/slack/) if you’d like to chat.
Keep project decisions in public issues or pull requests so others can follow them.
We help as time allows, and a friendly reminder is welcome.

## AI-assisted work

If you use AI to generate substantial code, prose, or scientific reasoning, tell us in the pull request and say how you checked it.
You’re responsible for the work you submit, including its accuracy, references, credit, and license compliance.
You can use routine completion or spelling help without adding a note.

Want to know more about how we work? Read about [community roles and package hosting](https://github.com/JuliaBayes/community/blob/main/README.md), [maintaining a package](https://github.com/JuliaBayes/community/blob/main/MAINTAINERS.md), and our [code of conduct](CODE_OF_CONDUCT.md).
