# Contributing

Questions, documentation, examples, teaching, scientific review, tests, code, and mentoring all help.
You don't need particular qualifications, and one contribution doesn't commit you to more.

Start with the package's contributor guide.
Small fixes can go straight to a pull request.
Discuss larger features, dependencies, API changes, and statistical changes first.
Early drafts and questions are welcome.

We strive to adhere to the principles laid out in [ColPrac](https://github.com/SciML/ColPrac), with local exceptions, including for solo maintainers.  
Keep changes focused and explain what you checked.  
Maintainers can help with tests and documentation.  
Reviewers explain which changes are required and which are suggestions.

Contributions follow the package license.
Credit includes non-code work, with consent for public naming. Paper authorship is a separate conversation.

## Finding help

Ask in the package's issues or Discussions.
For bugs, include versions, expected and actual results, and a small example without private data.
For help finding a contribution, open a [welcome issue](https://github.com/JuliaBayes/.github/issues/new?template=welcome.md).
You can also use `#bayes` on [Julia Slack](https://julialang.org/slack/). Keep decisions in public issues or pull requests.
We help as time allows. Reminders are welcome.

## AI-assisted work

Disclose substantial generated code, prose, or scientific reasoning in your PR, including how you checked it.
You remain responsible for correctness, references, credit, and license compliance.
Routine completion or spelling help needs no disclaimer.

See [community roles and package hosting](https://github.com/JuliaBayes/community/blob/main/README.md), [maintainer guidance](https://github.com/JuliaBayes/community/blob/main/MAINTAINERS.md), and the [code of conduct](CODE_OF_CONDUCT.md).
